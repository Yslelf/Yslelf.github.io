# XY 南昌总体架构

## 1. 目标

XY 是围绕真实地点内容（X）和同兴趣组局（Y）构建的本地社区。第一阶段优先验证“发现地点—阅读体验—产生互动”的 X 内容闭环。

## 2. 系统边界

```text
UniApp 客户端（H5 / App / 微信小程序）
        │ HTTPS / JSON / JWT
ASP.NET Core Web API
        ├── Application：用例、DTO、权限编排
        ├── Domain：用户、地点、帖子、互动规则
        ├── Infrastructure：EF Core、缓存、对象存储、地图服务
        └── BackgroundJobs：审核、通知、统计
               │
          PostgreSQL + Redis + 对象存储
```

## 3. 前端分层

- `pages`：页面组合与用户交互，不直接拼接 API 地址。
- `components`：跨页面复用的展示组件。
- `stores`：Pinia 维护跨组件状态和业务动作。
- `services`：Axios 请求、认证头、错误转换及 Mock/真实 API 切换。
- `types`：与 API DTO 对齐的 TypeScript 类型。
- `mock`：仅用于开发的稳定示例数据。

Element Plus、Arco Design 仅用于 H5 管理端或桌面页面。移动端公共页面使用 UniApp 原生组件和 `uni-ui`，保证 App 与小程序可编译。

### 多端 UI 策略

采用“UniApp 移动端优先、桌面 Web 渐进增强”的单业务组件方案：

- H5、App、微信小程序共享状态、DTO、服务层和交互逻辑。
- 以 750rpx 为移动设计基线，优先保证触控、安全区和底部操作。
- 760px 以上限制弹层和编辑器阅读宽度，避免表单无限拉伸。
- 1024px 以上启用桌面侧栏导航、趋势栏和宽主内容区。
- 桌面端不复制独立业务页面，只有布局容器与信息密度发生变化。
- 颜色必须使用 `--xy-*` 主题 Token，不复制参考社区的品牌红与品牌素材。

## 4. 后端推荐

- .NET 10 / ASP.NET Core Web API（若生产环境尚未升级，可先采用 .NET 8 LTS）。
- EF Core + PostgreSQL；空间检索启用 PostGIS。
- Redis 用于热点地点、Feed 游标和短期幂等键，不作为事实数据源。
- 图片和视频存对象存储，数据库仅保存对象键、尺寸、类型和审核状态。
- API 按业务能力组织，不按 Controller/Service 大目录堆放所有文件。

## 5. 关键决策

1. **先 X 后 Y**：先获得地点和内容供给，再构建依赖身份与信用的组局。
2. **游标分页**：Feed 使用 `cursor`，避免新增帖子导致页码漂移。
3. **坐标双字段**：保存 WGS84 原始坐标与高德 GCJ-02 展示坐标，明确坐标系，禁止隐式转换。
4. **软删除与审计**：用户内容使用软删除；审核、权限和资金动作追加审计日志。
5. **契约优先**：前端 `types`、Mock 和 OpenAPI DTO 保持字段一致。

## 6. 安全边界

- 客户端不能决定认证、奖励、信用或审核结果。
- 高德 Web Service 密钥仅保存在服务端；客户端 Key 需配置域名/包名白名单。
- 上传使用短期签名地址，服务端二次校验文件类型、大小和内容审核状态。
- 所有写操作支持 `Idempotency-Key`，避免移动网络重试造成重复记录。
